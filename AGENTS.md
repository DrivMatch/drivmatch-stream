# Stream Now — Mandatory developer / agent instructions

**USER DATA PROTECTION IS A RELEASE-BLOCKING REQUIREMENT.** Before changing UI, routing, storage, player, catalog, login, updates, or deploy, read `docs/STREAMNOW_FAVORITES_DATA_CONSTITUTION.md` and preserve its invariants. Never reset or discard user favorites or their local backups. Changes that put any saved list at risk must fail closed; do not merge/deploy without regression tests, backward-compatibility analysis and verified recovery.

Do not claim that favorites were restored based solely on their on-screen count. Account-owned favorites in D1 are canonical; **all interfaces** must read/write the authenticated account, never treat localStorage as a primary source. Distinguish integration in source code, simulated tests, production deployment and real-device validation; do not claim full real-world recovery, independent backup, or all-device durability without evidence. Always distinguish a user's manual rebuilding from automatic recovery.

The approved Stream Now canonical identity is the red/magenta brand in `00_CANONICO/`; never change its mark by inference. Preserve the channel catalog, user identities and all existing data.

## Mandatory universal scope
Every change must consider **all** Stream Now delivery surfaces: Android APK, Android AAB/Google Play, Android TV / Google TV (if introduced), Samsung Tizen and Samsung TV browser, LG webOS and LG browser, desktop browsers, iPad/iPadOS, iPhone/iOS, Android mobile browser, and future mobile/tablet/TV applications. No favorites, history, watchlist or user preference migration may be treated as safe merely because it works on one surface. Run `node --test tests/streamnow_favorites_data_safety.test.mjs tests/streamnow_universal_favorites_scope.test.mjs` as a mandatory gate in every packaging/deployment workflow. Never claim real-device validation from simulated tests; never claim synchronized favorites across devices unless the relevant interfaces actually read and write per-user server data. The D1 account store exists, but each platform requires explicit verification.

## Stream Now autonomous channel discovery and YouTube integrations
Before touching the daily scanner or its reports, read and obey `docs/STREAMNOW_CHANNEL_AUTOPILOT_OPERATING_PROMPT.md`. Required schedule: 02:00 primary, 04:00 independent Auditor A, 06:00 independent Auditor B; automatic recovery on audited failures. Research every global region on a rotating basis, all available countries and local languages, particularly news and sports; do not falsely claim all countries were covered in one run. Preserve ALL user favorites and keys. Use only publisher-permitted embeds and transparent platform attribution. Never hide YouTube branding or claim permission to retransmit.

## Canonical non-destructive account favorites invariant — ratified 2026-11-25
This is a binding constitutional design requirement, not a temporary feature flag. Before every change read Section 14 of docs/STREAMNOW_FAVORITES_DATA_CONSTITUTION.md. A verified user's favorites belong to the authenticated account (server-side user_id backed by D1), not to a TV, browser, localStorage key, login session or email string sent from the client. Every client must read the same account collection. No automatic deletion, reset, replacement, implicit cross-account migration or empty-list overwrite. P0 backend and D1 delete guards remain locked until explicit owner-approved Change Control plus independent backup and restore validation. Failing account sync must fail closed. Keep the original browser lists intact and import only by explicit user opt-in, additive union and read-back verification. Require tests/streamnow_multidevice_favorites.test.mjs in the pre-release gate, and physical platform tests before claiming hardware homologation.
